### 问题二：`In-Actor (Mode A)` 和 `External Harness (Mode B)` 到底是什么意思？

任何一个能干活的 Agent 都由两部分组成：
* **“大脑”（Harness / Agent Loop）**：负责维护对话历史、拼接 Prompt、调用大模型 API、解析大模型返回的 Tool Call。
* **“手脚”（Sandbox / 工具执行环境）**：负责真正执行 `bash` 命令、读写本地文件、跑 Python 脚本或编译代码。

这两种模式的区别，其实就是 **“大脑放在哪”**：

#### 1. `In-Actor Runtime (Mode A)` —— “大脑和手脚都在沙箱里”
* **怎么跑**：整个 Agent 程序（包括调用大模型的循环 + 执行本地命令的工具）全部打包进容器镜像，直接运行在 **Substrate Actor（沙箱）** 内部。像 **Claude Code CLI**、**Aider** 或你的**轻量 Coding Agent** 就是这种模式。
* **休眠时发生什么**：当 Substrate 对 Actor 执行 `Suspend`（内存快照）时，相当于直接把整个虚拟机/容器按了“暂停键”——**进程内存里的变量、正在跑的循环、改了一半的文件，一次性全部拍成快照存盘**。
* **痛点与你的改进**：因为“大脑”在沙箱里，如果它正在苦等大模型排队（HTTP 请求挂着），直接暂停沙箱会把网络连接掐断。所以需要你的**网关代持请求（Suspend-before-Queue）**。

#### 2. `External Harness (Mode B)` —— “脑体分离：大脑在外面，只有手脚在沙箱里”
* **怎么跑**：像 **DeerFlow 2.0**，它的“大脑”（LangGraph 编排器）作为一个普通的后端服务跑在沙箱外面（对话状态存在 PostgreSQL 数据库里）。当它想调大模型时，直接由外部服务请求 Dynamo；只有当大模型说“去执行 `pytest` 命令”时，外部大脑才通过网络远程操控 **Substrate Actor（手脚）** 去跑命令。
* **休眠时发生什么**：大模型在思考或排队时，沙箱（手脚）本来就是闲着的，随时可以休眠！但因为**大脑状态在 PostgreSQL 里，文件状态在沙箱快照里**，两边分家了——所以需要你做**两阶段状态对账（Manifest 对齐）**，防止恢复时“大脑记得改了第 5 步，沙箱文件却退回了第 3 步”。

> **一句话总结**：用 **DeerFlow 代表 Mode B（研究类 Agent）**，用 **轻量自研 Coding Agent 代表 Mode A（编程类 Agent）**，你就能把云原生 Agent 最核心的两种架构模式一网打尽！

  * `dynamo.mocker` 自带 `--speedup-ratio` 参数！如果在配合受控工具耗时缩比（比如把原本 60 秒的编译和思考按 1:10 等比例缩放为 6 秒），原本需要跑 **1 小时的多租户混部压测，在你的笔记本 CPU 上只需要 3~5 分钟就能跑完一组**，而且一分钱 API 费都不用花！

#### 绝招 2：“录制一次真实轨迹 + 无限次离线回放”（Trace Replay）
* **开发与录屏阶段（只调几次真模型）**：
  * 当你验证 DeerFlow 和 Coding Agent 功能正常、或者录制求职 Demo 视频时，接入便宜的 API（如 DeepSeek / Qwen API），只跑 **2~3 个真实任务**（花不了几毛钱，几分钟搞定）。
  * 在跑这几个真实任务时，把每一轮的 **输入 Token 数、输出 Token 数、工具执行耗时、沙箱内存占用** 记录成一份 JSON 轨迹文件（Trace）。
* **高并发消融实验阶段（P5 阶段跑 A~E 五组对比数据）**：
  * 你的压测脚本直接读取录制好的 Trace，驱动 50~100 个并发 Agent 会话去打 **真实的 Substrate 沙箱 + 真实的 Dynamo Rust Router + `dynamo.mocker`**。
  * 这样既有真实业务 Agent 的请求分布特征，又能在 **20 分钟内把 A、B、C、D、E 五组对照实验全部跑完**，而且每次结果 100% 可复现！

#### 绝招 3：最后补测真实 GPU 数据时，采用“缩比显存法”（花 5 块钱、半小时搞定）
如果你最后想在简历上堂堂正正写上“在真实 GPU + vLLM/SGLang 环境下验证”：
* 千万不要去租 8 张 A100 跑 70B 大模型、塞 1000 个并发！
* **正确操作**：在 AutoDL 上花 **2.5 元/小时** 租 **1 张 RTX 4090 (24GB) 或 L40S**，跑一个小巧的 **Qwen2.5-7B**。
* **核心技巧**：启动 vLLM / `dynamo.mocker` 时，通过 `--num-gpu-blocks-override 256`（或调低 `--gpu-memory-utilization`）**人为把可用 KV Cache 显存池限制到只够同时装下 4~6 个长上下文会话**！
* 这样一来，你只需要发起 **15~20 个并发会话**，在 **30 秒内** 就会立刻把 GPU KV Cache 打满，触发 ThunderAgent 的 `PAUSED` 排队和你的跨层调度！跑完 5 组对比实验总共不到 **30 分钟，花费不到 3 块钱**！
