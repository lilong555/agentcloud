Charge 汇总该 Actor 的 sandbox、container 和 checkpoint cgroup 叶，包含被计费的文件缓存；RSS 汇总宿主进程常驻页，共享页可重复计数。补采的最大采样间隙为 189.3 ms，首次运行最大间隙为 501.5 ms；峰值均按采样口径保存。

两次 Runner 内核分别为 `7.0.0-1017-azure` 与 `7.0.0-1014-aws`，成本表与统计分别保存。每格 3 批用于描述性标定，每格 1 批用于补齐采集覆盖；P95 是批次均值的插值分位，最终尾部结论仍需独立重复和采集开销对照。

两次运行都保留 Quiesce、RetainTag 独立耗时为 `null`。补采原始 Worker `io.stat` 同时暴露 `259:5` 与 `252:0` 两层设备；16 MiB 单路恢复后还新增了 Worker scope。`worker_io_write_bytes` 保持 `null`，首末原始计数保存在 `44729600983/worker-io-coverage.json`。阶段间的占槽、后台持久化和总时长存在重叠，消费端按各字段依赖使用。

每个运行目录包含 `costs.json`、`derived-batches.json`、`audit.json`、环境与清理回执、`provenance.json`。来源清单包含制品 SHA256、测量与提取源码身份、cannlab 原始数据位置及复算命令。原始逐事件、逐采样数据保存在 GitHub 制品与 cannlab 独立目录。
