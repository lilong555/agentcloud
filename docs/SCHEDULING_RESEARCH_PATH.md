# 调度算法研究路径与退出条件

研究以 Native 控制面、AgentLogs／FreeInference 事件负载与真实 gVisor MEMORY 成本为基础。阶段按依赖顺序执行。算法仿真通过 Tier-1 开放，最终实机算法比较通过 Tier-2 开放；固定准入语义与物理成本采集使用各自的验收入口。

## 范围与两级资格

核心观测集固定为请求接收、需求持久化、RPC 尝试与回执、容量拒绝、WAITING_CAPACITY 进出、Ready、资源释放和 Worker 资源采样。事件唤醒记录引用对应释放序号。完整 318 字段／71 事件／25 表契约作为长期架构规范保存，当前实现集中于上述闭合链路。

活动数据源固定为 AgentLogs 和 FreeInference。事件资格通过后冻结一个主数据集和另一个独立泛化集，泛化集始终隔离于调参。Alibaba 2017、TraceLab、ReproPatch 的既有记录保存在历史证据区。物理容量与成本直接采自 AgentCloud 运行时。

| 闸门 | 必需证据 | 运行入口 |
|---|---|---|
| Tier-1 | 两源事件级等待／工具分布与家族隔离时间切分；目标工作集／并发的 MEMORY 原始成本和查询表；事件唤醒与有界兜底的实测排队噪声 | `python3 -m bench.research_gate --require-simulation` |
| Tier-2 | Tier-1；完整重启一致性、观测开销、在线特征来源、闭环校准、多个独立种子与留出统计、冻结的误差容忍 | `python3 -m bench.research_gate --require-comparison` |

资格回执引用不可变原始文件与源码摘要。完整性检查通过表示引用与结构有效，资格状态由每项实测决定。主／泛化角色、排队延迟容忍和成本目标范围由注册表冻结。未完成项保留 `pending` 或 `partial`。

## 阶段一：Native 排队归因与事件唤醒

`bench.admission_diagnostics` 对现有归档按需求复算接收至 Ready、容量等待、RPC 和控制面／attach 余项。容量等待再结合完整 Worker fleet 采样划分为容量占满、有容量但仍在退避、有容量且已可重试、采样未知。跨源墙钟误差、采样转换区间和缺口随结果发布。

每行覆盖 8 个需求，累计值相加跨越并发区间。释放至下一次等待需求尝试的 P95 为 TTL2 0.666 s、v2 1.215 s，各有 7／6 个释放机会。这些是同一次历史运行的描述性归因；有容量区间包含 Worker 选择、资源可放置性及采样误差，性能收益使用独立干预验证。

当前控制路径在 Substrate Suspend 回执确认同一 Actor 已挂起且无 Worker assignment 后，持久登记释放，为最早的未通知需求保存 `retry_notified`、释放序号和 `slot_release` 来源，事务提交后唤醒。释放证明和快照 durable／retained tag 分别记录；生命周期回执保存释放序号以保证幂等。通知随持久需求保存，重启后继续消费；Substrate 验证实际放置。准入与策略操作各自使用有界执行池，每池上限为 `SchedulerConcurrency`，同会话保持互斥。兜底探测间隔为 5 秒，启动和本地释放后重新计时，轮流检查等待者。v2 的 KEEP／SUSPEND 决策函数沿用既有实现。

本次运行前冻结的去噪预算为：释放至通知需求尝试的 P95 ≤100 ms、最大值 ≤250 ms，兜底占全部容量重试的比例 ≤0.5，各租户已收到释放通知的需求最长等待 ≤250 ms。100 ms 对应 TTL2 阈值的 5%；250 ms 为单次异常容忍。兜底比例用于确认事件推进覆盖主要重试。租户指标统计获通知后的派发延迟，完整容量等待与总队列公平性同时独立报告。预算超出时该资格继续保持 pending，并据原始事件定位原因。

验收入口包含两部分：固定 Legacy／Native × TTL2／v2 语义负载，以及 `bench.native_restart` 的真实 MEMORY 检查。后者持有运行 Actor、保存初次 WAITING_CAPACITY、对 Coordinator 注入 SIGKILL、核验重启后的 Actor 身份与需求起点、释放后激活，随后验证恢复容量等待和 RAM nonce／PID／heap／AST／context 连续性。该专项关闭定时探测，单独检验事件推进；常规负载用于测量正常定时配置。

退出条件：逐需求耗时守恒；采样未知与时钟范围明确；事件唤醒延迟和兜底占比满足预冻结预算；最新源码的 MEMORY 重启验收及资源清理通过。

[运行 44706448532](evidence/native-admission/44706448532/artifact.json) 的四组对照完成 64/64 请求；TTL2／v2 的释放通知至尝试 P95 为 17.835／50.819 ms，兜底比例为 86.84%／83.33%，预算检查失败。MEMORY 重启专项在 holder 容量前提检查失败，实际执行尚未到 SIGKILL。所属资源清理成功。完整[分段归因与预算回执](evidence/native-admission/diagnostics/44706448532.json)保留失败分母。

## 阶段二：事件负载与分层物理成本

从 AgentLogs 模型／工具日志优先核验原生开始、完成、依赖和交互轮次；FreeInference 采用同一标准输入。字段按直接观测、推导、缺失分别登记。FreeInference 的工具 latency 保存为请求间 gap，工具执行时长在有原生起止的记录中单独提取。任务家族整体分组并按时间切分，跨切点家族采用冻结的隔离规则；失败、删失和未解析记录保留分母。到达重叠的结论范围为已发布子集。

MEMORY 成本表覆盖 16／64／128 MiB 与并发 1／4。记录 checkpoint、resume、RSS／charge、assignment 预留、真实快照写入与磁盘水位；逻辑快照大小、文件分配和设备写入分别列示。原始测量与 P50／P95 查询表分开，保存硬件、存储、样本数、批次及来源哈希。P50／P95 表示样本分位数，不确定性另用批次重采样区间和留出误差表达。

退出条件：两源合格因果窗口、主／泛化角色和无泄漏切分冻结；成本模型覆盖目标坐标且关键物理指标齐全；阶段一噪声资格通过。Tier-1 随上述证据开放。

## 阶段三：闭环模拟器与离线参照

Go 离散事件模拟器复用控制面策略决策接口。只向在线策略暴露 `available_at ≤ decision_at` 的观测。父模型完成、工具依赖与 join、恢复排队、Actor ready 和磁盘预算共同决定后继事件；每次策略改变均传播到后续时间线。

使用相同 Native 输入校准首次／恢复排队、恢复次数、Actor 预留 GB·s 和总完成时间。校准误差预算小于拟证明收益，并核验策略排序。小切片采用精确搜索／动态规划或 MILP；可行离线解、最优性证明与松弛下界分别标明。近似解提供可行参照，证明下界需要明确的松弛方向。

退出条件：延迟干预与分叉前决策一致性测试通过；实机校准通过；基线与 Oracle 使用相同动作、安全、容量和成本约束。

## 阶段四：形式化与 v3 候选

有限槽位下构造局部驻留决策损害全局首次等待的可复算反例，给出适用假设和外部性来源。反例证明存在失效实例；一般性结论须有对应条件与证明。状态、动作、目标和硬约束覆盖驻留、挂起、准入顺序、工作集、磁盘、租户与等待年龄。

候选机制为按可见等待阶段条件化的分布、槽位与磁盘机会成本、预测失准时的有界回退。比较统一使用累计成本单位：例如驻留成本率对剩余等待积分，随后与 snapshot／resume／journal／动作条件 KV 差额和磁盘成本比较。KV 缺测保留缺测状态，GPU 校准沿用独立资格。

双峰分布由数据检验，影子价格或 Lyapunov 性质由明确假设推导，ski-rental 的单对象保证在共享容量模型中重新证明。三项机制均为待验证候选。

基线包括 TTL2、TTL15、v2、FIFO 准入、简单队列水位驱逐、分布预测 ski-rental 和离线参照。FIFO 是准入排序维度，需与明确的驻留策略组合比较。输出资源／快照写入／交互尾延迟 Pareto 面、首次与恢复队列、完成率及租户公平；消融逐项移除分布、年龄价格、磁盘乘子和鲁棒界，并覆盖错误预测、突发与磁盘压力。

Go 条件：独立留出与泛化集均有超出误差的稳定优势，优于强 TTL、v2 和简单启发式，关键 64／128 MiB 边界改善且约束满足；同时报告离线参照差距。无独立收益的模块裁剪，未达 Go 保留负面结果并停止晋级。

## 阶段五：实机终审与交付

仿真 Go 后接入通过验证的 v3，执行 Native MEMORY 下 N=32／64、多种子、64／128 MiB 的同机配对终审，补齐观测开销、重启、在线来源、置信区间、误差预算和一键复算。真实 GPU 联合观测按实际资源单独验收。

终审报告连接问题与反例、数据资格、成本表、闭环校准、模型性质、消融和实机结果。简历只选用通过终审且可精确定位源码与原始证据的结果；ReproPatch 的压缩比例采用其自身冻结分母。上游 PR 按独立正确性与维护者负担评估。

最终退出条件为理论假设、源码、实验、图表和简历数字具有完整可复算证据链。
