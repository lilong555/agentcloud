# 指标字典说明（建议设计 v1.1，尚未实现）

本附件定义后续研究的 40 项指标。`metric_dictionary.csv` 包含数学定义、单位、统计总体及分母、测量窗口、源事件或规范化表、缺失与删失处理、验收方法和解释限制。**所有数值门槛都是建议的新实验设计目标，未经本轮实机验证；没有以新门槛追溯重判旧实验。** v1.1 同步核心契约新增的 5 个关联 ID 和 2 个原生 prefill counter 的引用，没有增加调度算法或运行时实现。

## 1. 统一统计与计时口径

所有 ns 从十进制字符串解析为精确整数或 `DECIMAL(38,0)` 后再相减，以 `duration_ns / 10^9` 转为秒。GB 使用十进制 `10^9 byte`。单调时刻只在同一 clock domain 与合法 incarnation 内相减；跨域差值必须附 UTC 校正误差界，无法确认则保留空值。等待、失败、超时及真正的零耗时不混用。

每个指标报告 `run_id`、数据版本、源码 commit、硬件配置、执行模式、采样策略、窗口、分母和计数。预先冻结初始化、工作及清理阶段的边界，保存三者的分项。与历史 Gate 2 比较时保留其 `all_workspaces_ready` 至最终释放的资源口径，同时补充首个请求到达之前后的全周期成本。

TTFT 必须注明 token 的观测位置：应用可见、gateway 接收或引擎发出；首 token 排除 SSE 心跳和不含内容的增量。用户到达至首 token、API 提交至首 token、API 完整响应、引擎排队、引擎服务分别计算。缺少用户到达时间的 trace 不能产生真正的用户交互 TTFT。公共模型 span 的 wall duration 通常包含其原运行系统中的排队与网络因素。

首次容量准入、恢复容量准入、模型 dispatch 队列分开。已有 benchmark 的 `gateway_queue_seconds` 和 Coordinator 的 `gateway_queue_ms` 具有不同边界，不能只按名字或单位换算合并。

建议固定 Type 7 样本分位插值，并在小样本时同时提供排序值或经验 CDF。先算各配对 trial 的 P95，再对配对差进行推断；合并所有请求后的 P95 回答另一个问题，不可替换前者。均值、每 trial 分位、跨 trial 均值和租户加权分位必须分别命名。

## 2. 先过统计可信度闸门

第一道闸门是解析正确、单位明确、身份与因果关系可恢复、起终事件覆盖和完整分母。单条样本或少量窗口只支持 Schema、关联及可用性核验；本附件不给这些样本补出长尾结论。

每项结果同时列出请求、Session、独立 workspace/family、时间块及运行 seed 数量。相关请求不能当作同等数量的独立样本。bootstrap 应以实际独立单位保留完整关联结构；配对比较必须同步重抽同一 workload/runner 对。多个 seed 共享工作负载时，还应区分负载泛化不确定性与运行噪声。

**建议的报告门槛**是：P95/P99 至少具有 20 个落入目标尾部的观测，并跨越足够的独立 family 或运行块；同时给出 cluster 置信区间，其宽度足以区分预先认为有意义的收益。20 是规划参考，不是统计充分性的定理。P99 在独立同分布假设下，2,000 个观测也只对应约 20 个期望超越值；高度相关数据的有效样本量更小。没有足够独立块、删失占据目标尾部或区间过宽时，标注“暂不具备统计结论”，只展示描述性数据和置信限制。

对于单开发者预算，先用 CPU 分析和小规模真实回放确定效应量及方差，再冻结重复次数和正式测试预算。不要按结果反复追加运行直到显著。预先指定主指标、尾部退化容限与完成率约束；次级指标标为探索性并考虑多重比较。

## 3. 删失、失败与选择偏差

成功完成 Session 的 E2E 是条件于成功的分布。它必须与 `N_success / N_planned`、未投递比例、失败比例和 SLO Goodput 联合解释。提前失败可以让到任意终态的 RMST 变短，因此 RMST 也不能单独证明系统更好。

观测窗口关闭产生的行政右删失、用户取消、失联、工具失败、策略主动终止分别记录。KM 或 IPCW 只在相应独立或条件独立删失假设可辩护时使用；信息性取消或失败不能自动当作成功完成时间的普通删失。必要时改报可识别区间、竞争风险的累计发生率和敏感性结果。

剩余等待预测按预声明 landmark 或 episode 等权评估，避免长 episode 因决策 tick 更多而占据过多权重。完成样本的 MAE 命名为 `MAE_complete`，并报告 known/unknown、完成/删失和所有 eligible episode 的分母；被策略选中的 SUSPEND 子集不代表总体精度。现有 v2 预测 0.75 分位时，MAE 是辅助诊断，pinball loss 与校准更对应其输出含义。

IPCW Brier 定义中的 `Y=min(T,C)`、`δ=1{T≤C}` 均相对于相同 landmark；条件删失模型使用 `G_j` 而非混用无条件 `G`。共同 horizon 必须有正的删失生存支持。建议 `G≥0.05` 仅作为待验证的公共支持门槛并做敏感性分析。评测程序可以在封存后读取测试标签来计算指标；这些标签及用于评价的删失模型结果不得返回在线策略、调参或训练路径。拟合与交叉拟合协议在打开测试结果前冻结。

未知采样概率不填 1；志愿者数据、筛选后的优质窗口与 benchmark 场景不能通过加权自动变成真实生产总体。条件于这些数据的实验结论应明确所覆盖的人群及任务。

## 4. 资源、成本与缓存的解释边界

Actor reservation GB·s 是实际 assignment 中的逻辑预留积分。物理内存 GB·s 需要独立的 cgroup charge、RSS 或 PSS 采样；三种计量口径分别报告。父子 cgroup、guest 与 sentry、共享文件页不能重复求和。安全等待空占还要求确认没有活动工具或后台进程；它表示潜在释放机会，未扣 checkpoint/resume 的物理成本。

累计计数按 stats epoch、进程重启和 reset 分段。字典中的 `resource_metrics.<name>` 表示规范化长表 `metric_name=<name>` 的值，并非额外 SQL 列；JSON 对应 `resource_usage` 中的明确叶字段。物理存储库存、GC 回执和实际 prefill-token 原生计数是部分指标仍需补充的采集来源，不能由现有契约结构存在推断其已实现。

快照逻辑字节、压缩后 allocated bytes、应用写入、文件系统写入、设备物理写入与网络传输分别保存。`Tag × 平均快照大小` 属于有假设的外推；累计写入不等于磁盘峰值占用。异步上传尾部、临时文件、重试和 GC 延迟必须进入对应窗口。`checkpoint_total`、`resume_ready` 等聚合阶段与子阶段不可重复相加。

KV 索引命中是决策前可见代理；引擎 usage 中的 cached tokens 才是本次请求实际命中的观测，仍须区分真实 GPU 和 Mocker。`input_tokens − cached_tokens` 只能作为非缓存输入量代理，不自动等于所有重算或实际执行的 prefill-token 数。v1.1 增加 `resource_usage.engine_prefill_tokens_executed_total` 与 `engine_prefill_tokens_recomputed_total` 的设计接口，单位为 token_execution，同一位置重复执行重复计数；接口存在不表示原生采集已经实现。

两计数要求 inference_worker scope、包含引擎实例和原生标签集的 scope_id、已知 counter_reset、真实 source_update_at 与可追溯的源 counter 名称及实现版本。按实例/reset 分段计算 delta；重置边界无完整样本时保持增量未知。重算只涵盖原生计数明确识别的原因。不得把 Worker 总量复制为每请求工作量，不得将 TP/PP 的相同逻辑 token 副本重复相加。原生计数缺失时填 null 并报告采集覆盖，不能把 input−cached 代理填成实际执行或重算计数。

## 5. 数据质量和观测扰动

完整性分母来自已提交 outbox 水位、源开始/结束标记、冻结计划与操作回执。只看收到的事件无法证明未丢失；source sequence gap 必须先排除设计采样、过滤和非研究事件。重复、乱序与迟到是可清洗现象，但原始副本与原始接收计数必须保留。相同 event ID 对应不同 payload 的冲突不能覆盖。

资源覆盖按所有应观测 scope 的完整窗口计算，包括完全缺失的 Worker。最后一个真实更新样本的有效区间至 `min(window_end, sample_time + g)`，不是无期限延续。读取一分钟缓存一百次仍只有一次更新信息，不能提高独立覆盖。没有容量或物理上界的缺口应保留积分上界未知。

字典中的覆盖 ≥99%、积分不确定性 ≤2%、2 秒 TTL 场景的 UTC 不确定性 P99≤5 ms、遥测 CPU 增量 ≤5% 等均是新研究的候选设计预算。是否适用取决于实际效应量、机器能力和实验目标，应先小规模校准再冻结。达到采样覆盖本身不能证明积分准确；必须结合边界事件和短时高频参照测量验证。

遥测开销采用同一策略、相同输入和相同资源预算的成对 on/off 或低/高采样实验，随机化执行顺序，测量进程 CPU、内存、决策延迟及端到端影响。只测试纯决策函数会遗漏序列化、导出、存储与数据库争用。

## 6. 本次附件的验证边界

本次仅检查 40 个指标 ID 唯一、必填描述完整、数值门槛均标为建议、引用与 v1.1 契约一致、附件可读，以及指标生成过程不意外改写核心文件。核心文件本次依要求由 v1.0 升级到 v1.1，变更范围由 validation_report 的七字段差异记录说明。没有实现指标 ETL、运行完整查询、重新运行 AgentCloud 或确认任何数值验收门槛已达到。`metric_validation_report.json` 保存检查结果及文件 SHA256，便于与主报告一起封存。
